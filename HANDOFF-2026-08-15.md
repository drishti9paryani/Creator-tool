#### The shot cap, in detail

`deriveScenes()` was capped at 4 scenes × 3 shots = **12 shots = 48 seconds**.
The archetype's beats are now treated as **acts**, with scenes inside each act
scaling from a `targetSeconds` parameter:

| Target | Scenes | Shots | Runtime |
|---|---|---|---|
| 32s | 4 | 12 | 48s (act-structure floor — deliberate) |
| **360s (default for `video`)** | **30** | **90** | **360s** |
| 600s | 50 | 150 | 600s |

`SHOT_ANGLES` went 3 → 12 entries (offset per scene, no angle repeats back to
back). New `SCENE_MOVES` pool of 12 subdivides an act. `SECONDS_PER_SHOT = 4`
and `DEFAULT_TARGET_SECONDS` are exported constants.

#### The Character Bible, in detail

Characters persist under their **own IndexedDB key**, separate from projects, so
deleting a project does not delete the cast and one character is reusable across
every project. `canonPrompt()` is the single place identity text is assembled.
`mergeBible()` is pure and exported; a stale import can never overwrite newer work.

## Gotchas

**`IMAGE_LIMIT_PER_PROJECT` defaults to 8 — and that is now actively harmful.**
A 6-minute project needs ~90 storyboard images. 82 of them will fall back to
placeholder art with a warning toast. This was harmless when projects capped at
12 shots; today's change made it a blocker. **Deliberately left at 8** — raising
a spend guard is a money decision and was not authorised. Raise it before any
live run.

**The store is IndexedDB and loads asynchronously.** No synchronous read. On a
hard refresh or a direct link, `projects` is empty for the first render or two.
Any screen that decides "this project doesn't exist" must gate on `useHydrated()`
from `lib/store/useHydrated.ts` first. Getting this wrong told testers their work
was gone. The new character store has the same property.

**Names must come from curated pools; the user's idea goes only in
descriptions.** Regressed three times with three symptoms: titles like "The Two
Moment After", a prop named "RETIRED", characters named "LAGOS" and "PEERING".
Rule and exceptions live in `lib/ai/story.ts` under `NAMING RULE`. Regression
tests cover each. Do not splice keywords into a name slot.

**Deterministic pickers collapse on modular arithmetic.** `pick(pool, seed +
variant * K)` returns the same entry whenever `K` is a multiple of the pool
length — this made "Regenerate options" look like a no-op twice. Derive variants
by hashing a composite key, not by adding an offset. **Related, new this
session:** hashing into `SCENE_MOVES` produced acts that opened on "Refusal".
That pool is written as an escalation and must be walked **in order**.

**`next build` while `next dev` is running corrupts the dev server's chunks.**
They share `.next`. Stop the dev server first.

**`npm run lint` is not configured** — drops into an interactive ESLint setup
prompt and hangs a non-interactive shell. `next build` runs linting anyway.

**`@vitejs/plugin-react` cannot be installed** — needs vite 8, vitest 2.1.8 pins
vite 5. JSX is transformed via `esbuild: { jsx: "automatic" }` in
`vitest.config.ts`. Don't "fix" this by installing the plugin.

**`npm run keys` needs a real terminal.** Refuses when stdin isn't a TTY and
prints the command to run instead. Deliberate.

**Windows line endings** — git warns `LF will be replaced by CRLF` on nearly
every commit. Cosmetic, ignore.
