# PROTOTYPE — AI Video Creation Studio

Turn a story idea into a production package: three story options, a cast of
characters and locations with generated art, a scene-by-scene shot list with
screenplay, a storyboard you can play back as an animatic, and a single-file
export you can email to anyone.

Built with **Next.js 15 (App Router) · TypeScript · Tailwind CSS · Zustand**.

## Quick start

```bash
npm install
npm run dev        # http://localhost:3000
```

Runs in **demo mode** by default — no API keys, no cost, no network. The story
engine is real: type any idea and you get a story about *that idea*, with
characters, locations, scenes and screenplay derived from it.

## The two modes

| | Demo mode (default) | Live AI |
|---|---|---|
| `AI_PROVIDER` | `mock` | `real` |
| Keys needed | none | `OPENCODE_API_KEY` + `OPENAI_API_KEY` |
| Stories | generated locally, on-topic, deterministic | written by Gemini |
| Art | style-tinted placeholder placards | generated by OpenAI Images |
| Cost | zero | cents for text, dollars for images |

The home page shows which mode is active (a "Demo mode" / "Live AI" pill in the
header), so a tester is never guessing.

### Switching to live AI

1. Open `.env.local` and paste your keys:
   ```
   AI_PROVIDER=real
   OPENCODE_API_KEY=...
   OPENAI_API_KEY=...
   ```
2. Restart the dev server.

`.env.local` is git-ignored — keys never reach the browser or git. All provider
calls run server-side in `app/api/ai/`. On boot, a health check logs each
provider as `ok`/`FAIL`, so a missing or unfunded key shows immediately in
`dev.err.log`.

### Spend guard

Live mode is metered so a shared link can't run up a bill:

| Variable | Default | Meaning |
|---|---|---|
| `IMAGE_LIMIT_PER_PROJECT` | 8 | Generated images per project |
| `IMAGE_LIMIT_PER_HOUR` | 60 | Generated images per hour, all users |

Hitting a limit falls back to placeholder art **and tells the user why** — it
never crashes and never silently pretends.

### When live calls fail

Every live call falls back to local output so a demo can't die mid-flow. The
fallback is always announced with a warning toast naming the reason. Silent
fallback is worse than an error: it's indistinguishable from the AI simply
being bad.

## What works, and what doesn't

**Works end to end:** format choice, idea entry, three story options,
regeneration, editable summary, 12 visual styles, cast + location generation,
manual asset creation, per-asset iteration by prompt, scene/shot management,
AI screenplay writing, storyboard frame generation, animatic playback, HTML
export, natural-language command bar.

**Not in this build:** rendered video (no video model wired — the Editor plays
a storyboard animatic and says so), voice-over, user accounts, server-side
storage or sharing.

**Storage:** everything lives in the browser's IndexedDB. Projects don't follow
a user between devices or browsers, and clearing site data deletes them. Use
**Export storyboard** to produce a portable file.

## Scripts

- `npm run dev` — dev server
- `npm run build` — production build
- `npm run start` — serve the production build
- `npm run test` — Vitest (21 tests covering the story engine, placeholder art
  and the spend guard)

> Don't run `next build` while `next dev` is running — they share `.next` and
> the build corrupts the dev server's chunks.

## Structure

```
app/                     routes: /, /create (wizard), /project/[id]/{assets,shots,editor}, /api/ai/[op]
components/{wizard,workspace,home,ui,brand}
lib/ai/
  types.ts               domain types + the AIProvider interface (the one seam)
  provider.ts            selects mock or real from AI_PROVIDER
  story.ts               offline story engine — outlines, scenes, shots, assets
  placeholder.ts         deterministic SVG placard art
  degraded.ts            per-request fallback tracking (surfaced as toasts)
  budget.ts              image spend caps
  prompts.ts             all system prompts — the one place to tune the model
  mock/ real/ http.ts
lib/store/               Zustand store (persisted to IndexedDB)
lib/export.ts            single-file HTML storyboard export
data/                    formats, suggestions, styles
```

### Extending it

`lib/ai/types.ts` defines `AIProvider`. Implement that interface, select it in
`lib/ai/provider.ts`, and no UI code changes. Every generative call carries its
full context (scene, screenplay, cast, style, format) rather than bare ids, so a
new backend has everything it needs.

To change model behaviour, edit `lib/ai/prompts.ts` — nothing else.
